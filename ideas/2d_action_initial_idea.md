# 2Dアクション 初期アイデアメモ

最初のテンプレートにサンプルとして書いていた内容を、アイデアメモとしてまとめたもの。**何も確定していない。** 新しいプロジェクトのビジョン検討で、たたき台として使う。

## コンセプト

- レトロゲーム風の2D横スクロールアクション。
- 敵の攻撃を観察し、攻撃の種類に応じて防御行動を選び、反撃の隙を作る戦闘が中心。
- プレイ時間は約6時間。

## 柱の候補

1. Readable Combat
2. Responsive Controls
3. Meaningful Enemy Patterns
4. Exploration With Purpose
5. Strong Visual Feedback
6. Compact but Dense World

## 体験したい瞬間

- 敵の攻撃を見切ったときに気持ちいい。
- 初見では苦戦するが、再挑戦すると上達をはっきり感じる。
- 新しい敵を見た瞬間に「こいつはどう戦うんだ？」と思う。
- ボスを倒したときに、運ではなく理解と技術を感じる。
- 短い探索でも発見の報酬がある。

## 戦闘

- コアループ: Observe → Recognize → Defend → Create Opening → Attack → Recover → Repeat
- 攻撃には視覚的な予兆を持たせる。攻撃の種類と対応の案:
  - 通常攻撃 → Block / Dodge
  - Parry可能な攻撃 → Parry
  - Unblockable → Dodge
  - 広範囲攻撃 → 距離を取る / Roll
  - 遠距離攻撃 → Dodge / Block
- 戦闘のゴール: 入力遅延を感じさせない。ヒット・被弾・Parry成功が明確に伝わる。モーションだけで敵の次の行動を判断できる。連打だけでは安定して勝てない。防御成功には明確なリターンがある。
- プレイヤーアクションの候補: Move, Jump, Light Attack, Heavy Attack, Block, Parry, Dodge / Roll, Ranged Attack, Interact
- スタミナ制は必須にしない。戦闘の面白さを損なうなら採用しない。

## 敵・ボス

- 敵の違いはHPではなく、プレイヤーに求める判断の違いで作る。
- プロトタイプの敵の案: 基本の近接（攻撃と回避を学ぶ）、重量級（タイミングと距離管理を学ぶ）、高速（反応速度と優先順位を学ぶ）。
- ボスは「HPの多い敵」ではなく、学んだ戦闘原則を組み合わせて試す存在。6時間規模なら主要ボスは4〜6体が目安。

## ステージ・成長

- 新しい敵やギミックは、まず安全な状況で紹介し、その後に既存の要素と組み合わせる。
- 難易度は敵のHPではなく、配置・組み合わせ・地形・攻撃タイミングで上げる。
- 1ステージあたり40〜60分が目安。
- キャラクターの数値の成長と、プレイヤー自身の技能の向上を両立させる。数値を上げるだけで戦闘を解決できる設計にしない。

## アート

- レトロゲームの視認性と、現代的なアニメーション品質を両立する。
- 参考: Tails of Iron（構図、コントラスト、シルエット、戦闘演出）。固有のデザインはコピーしない。
- 強いシルエット、読みやすい攻撃ポーズ、敵ごとに違うシルエット、一貫した頭身。
- 背景と前景を明確に分け、プレイヤーと敵を見やすくする。
