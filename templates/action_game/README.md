AIと共同で制作するアクションゲームの設計・開発Knowledge Base。

## 文書の扱い

`01_design/` はゲームの仕様。
`02_reference/` は参考資料・分析。
実装を開始する前に、AIは関連する仕様書を確認すること。

## AIとの開発方法

このプロジェクトは、AIに一度に全仕様を決定させるのではなく、**人間とAIが対話しながら段階的に設計を進める**。

### 基本フロー

1. 現在の設計文書をAIが確認する
2. 未決定事項や矛盾点をAIが提示する
3. 人間とAIが対話して仕様を決定する
4. 決定した内容を関連するMarkdownファイルへ反映する
5. 次の設計項目へ進む
6. 必要に応じて過去の仕様を見直し、関連文書も更新する

### AIによる勝手な仕様決定を禁止する

`TBD` や未定義の項目について、AIは重要なゲームデザインを勝手に決定してはならない。

AIは以下を行う。

* 選択肢を提示する
* メリット・デメリットを説明する
* 他の仕様との矛盾を指摘する
* 必要な仕様を質問する
* 仮案を提示する

最終的なゲームデザインの決定は人間が行う。

### 一度に進める範囲

原則として、1回の作業では1つの設計テーマに集中する。

例:

* プレイヤーの移動
* 攻撃システム
* Parryの仕様
* 敵の攻撃パターン
* ボス設計
* ステージ構造

複数のテーマにまたがる変更が必要な場合は、変更前にその影響範囲を説明する。

### 設計の確定

仕様が人間によって承認された場合、その内容をMarkdownファイルへ反映する。

会話の中だけで決定した仕様を正式な仕様として扱わない。

**Markdownファイルに記録されている内容を正式な仕様とする。**

### 設計の進行

設計は上流から下流へ進める。

概念 → システム → 具体的な数値 → 実装仕様

の順に詳細化する。

後から新しい発見があった場合は、既存仕様を変更してよい。
その場合は関連する設計文書との整合性を確認する。

### AIへの基本姿勢

AIは「答えを出す装置」ではなく、ゲーム設計を一緒に検討する共同作業者として扱う。

**質問 → 対話 → 決定 → 文書化 → 次の質問**

というサイクルを基本とする。
