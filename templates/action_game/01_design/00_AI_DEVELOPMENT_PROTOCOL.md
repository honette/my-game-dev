# AI Development Protocol

## 目的

AIを単なるコード生成器ではなく、ゲームデザイナー・プログラマー・アーティスト・QAの共同作業者として扱う。

## 基本原則

1. 一度にゲーム全体を実装しない。
2. 小さく実装 → プレイ可能化 → テスト → 修正 → 次へ進む。
3. 仕様書にない重要な仕様を勝手に追加しない。
4. 既存仕様と矛盾する場合は、実装より先に仕様の更新を提案する。
5. 変更時は関連する設計文書も更新する。
6. アセット生成では既存アセットとの視覚的一貫性を優先する。
7. 「それっぽい」実装より、プレイヤーが実際に遊んだときの操作感・可読性を優先する。

## 開発フェーズ

### Phase 0 — Design
ゲームビジョン、コアゲームプレイ、戦闘、プレイヤー、敵、ステージ、アート方針を定義する。

### Phase 1 — Combat Prototype
プレイヤー1体、敵2〜3種類、基本攻撃、防御、回避、被弾、死亡、リスタートだけを実装する。

### Phase 2 — Vertical Slice
短い1ステージと1ボスを完成させ、ゲームの最終品質に近い形で遊べる状態にする。

### Phase 3 — Content Production
ステージ、敵、ボス、装備、探索、NPC等を追加する。

### Phase 4 — Balance
難易度、敵配置、報酬、進行速度、チェックポイントを調整する。

### Phase 5 — Polish
アニメーション、VFX、SE、UI、演出、チュートリアル、アクセシビリティを磨く。

### Phase 6 — QA
最初から最後までプレイし、進行不能、セーブ破損、Soft Lock、操作不能、重大な視認性問題を修正する。

## AIへの作業ルール

各作業の開始時:

1. 関連する設計文書を読む。
2. 現在の進捗を確認する。
3. 今回の変更範囲を明示する。
4. 実装する。
5. テストする。
6. 変更内容を進捗文書に記録する。

大規模な変更を一度に行わない。

## 完了条件

「コードを書いた」ではなく「プレイヤーが意図した体験を実際にプレイできる」ことを完了とする。
