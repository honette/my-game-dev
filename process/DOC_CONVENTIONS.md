# Document Conventions

ゲームプロジェクトの文書の構成と書き方の約束。すべてのプロジェクトに共通する。

## プロジェクトの構成

```
<game_name>/
  README.md          このゲームの概要（タイトル、一言コンセプト、ジャンル）
  PROGRESS.md        現在のフェーズ、次のタスク、Decision Log
  01_design/         正式な仕様
    00_GLOSSARY.md   用語集
    01_〜            各領域の仕様（構成はジャンル別テンプレートによる）
  02_reference/      参考作品・分析
  03_handoff/        実装側への引き渡し書
```

実装側に渡すのは `01_design/` と `03_handoff/` だけ。`PROGRESS.md` と `02_reference/` は設計作業用で、渡さない。そのため、仕様は `01_design/` の中で完結させる（`02_reference/` や会話の内容を前提にしない）。

## 文書のステータス

`01_design/` の各文書は、先頭に front matter でステータスを持つ。

```
---
status: draft
---
```

| status | 意味 |
|---|---|
| `draft` | 検討中。`TBD` や `> 検討中:` が残っている。 |
| `agreed` | 人間が内容全体を承認した。変更は可能だが、関連文書との整合性を確認する。 |
| `locked` | 引き渡し書から参照され、実装側に渡した。変更するときは Decision Log に記録し、影響する引き渡し書を更新する。 |

ステータスを上げるのは人間の承認があったときだけ。

## 本文中の記法

- `TBD` — 未着手の項目。
- `> 決めること:` — テンプレートが用意した検討の観点。項目が決まったら消す。
- `> 検討中:` — 議論したが決まらなかった論点。論点・出た選択肢・人間の傾向を2〜4行で書く。決まったら消して本文に置き換える。
- AI の仮案は、人間が承認するまで本文に書かない。

## 用語集（00_GLOSSARY.md）

複数の文書で使う用語（例: Parry、Telegraph、Recovery Window）は用語集で定義し、本文はその意味で使う。新しい用語を仕様に入れたら、同時に用語集にも追加する。

## PROGRESS.md

- **Current Phase** — `DESIGN_PROTOCOL.md` のフェーズ。
- **Completed** — 確定した設計テーマ（細かい決定は Decision Log へ）。
- **Current Focus** — 次に取りかかる設計テーマを1つ。
- **Next Tasks** — 予定しているテーマの順序付きリスト。
- **Decision Log** — 1件1行。`- YYYY-MM-DD — 決定内容（反映先: 文書名 / 理由 / 却下した案）`

## 引き渡し書（03_handoff/）

フェーズごとに `PHASE_<N>_<NAME>.md` を1つ作る（例: `PHASE_1_CORE_PROTOTYPE.md`）。実装側の AI が最初に読む入口であり、次を書く。

- このフェーズで作るもの・作らないもの
- 参照すべき設計文書と見出し（参照先は `agreed` 以上であること）
- 完成の判断基準（どう遊べたら完成か）
- 実装側に任せてよい判断と、設計側に確認が必要な判断

引き渡したら、参照している文書を `locked` にする。
